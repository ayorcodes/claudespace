# Implementation Design: npm as the primary distribution channel

Status: **Ready for implementation** — 2026-09-04
Scope: macOS only (Windows backend work stays behind the psmux ADR; this
design leaves the per-OS seams open but implements only `darwin`).

## Architecture Decisions

### AD1 — The npm package lives at the repo root, not a subdirectory (resolves researcher Unknown #1)

`package.json` sits beside `pyproject.toml` at the repo root; the whole Python
tree (`claudespace/`, including `claudespace/assets/`) is the package payload.

**Reasoning.** npm can only tarball files at or below the `package.json`
directory — a subdirectory package could not include the sibling `claudespace/`
Python tree without a copy step, and D2 requires the provisioned `.venv` to sit
*inside* the package directory so `npm rm -g` removes it. Root is therefore the
only layout where the tarball is simultaneously (a) the Python package pip can
build from, (b) the home of `.venv`, and (c) the home of the `bin/` shims that
must sit next to the Python tree they wrap. `CLAUDE.md` documents no packaging
directory convention, so there is no project rule to defer to.

New root-level files: `package.json`, `.npmignore`, `bin/` (committed shims),
`scripts/` (the JS postinstall + a shared node provisioning helper). Nothing
under `claudespace/` moves.

**Rejected:** an `npm/` subdirectory. It cannot reach the sibling Python tree
at pack time without duplicating it, and would put `.venv` outside the tree pip
installs, breaking D2's "uninstall removes everything".

### AD2 — All seven console scripts are registered in npm `bin`, not just `claudespace` (clarifies ADR D0/D1)

The ADR body says "`bin` stays `{ claudespace: … }`". Read literally against the
Technical Brief that is wrong: the Stop hook fires the bare name
`claudespace-handoff`, the PreToolUse guard fires `claudespace-guard`, and
`claudespace-msg` / `claudespace-tmux-persist` are invoked bare too — all
resolved through PATH (`pyproject.toml [project.scripts]`, 7 entries). Only
names listed in npm `bin` land on PATH. Registering only `claudespace` would
leave the other six unresolved and reproduce D1's "silently dead pipeline".

The ADR's `{ claudespace: … }` is the statement that *the daily command name is
unchanged* by the scope, not an exhaustive `bin`. `bin` therefore lists **all
seven** shim names. This is a clarification, not a departure — it is what D1's
own reasoning requires.

**Reasoning / mechanics.** Each `bin` entry points at a committed POSIX shim in
`bin/` (AD3). The shim self-resolves its real path (it is reached through an
npm-created symlink in the global bin dir), self-heals a missing `.venv` (D5),
then `exec`s the matching console script inside `.venv/bin/`.

### AD3 — Shims are committed static `sh` scripts that self-resolve and self-heal (D3, D5)

`bin` targets must exist in the tarball because npm links `bin` during reify,
*before* postinstall runs — so the shims cannot be generated by postinstall.
They are committed `#!/bin/sh` files (npm generates the `.cmd`/`.ps1` Windows
wrappers itself). Each shim:

1. Resolves its own real location through the npm symlink using a portable
   POSIX readlink loop (BSD `readlink` on macOS has no `-f`), yielding
   `PKG_ROOT`.
2. If `$PKG_ROOT/.venv/bin/python` is missing, runs the provisioner
   (`node "$PKG_ROOT/scripts/provision.js"`) — this is D5's self-heal for
   `--ignore-scripts` / pnpm installs.
3. `exec "$PKG_ROOT/.venv/bin/<console-script>" "$@"`.

Keeping node out of the steady-state path (only the missing-venv branch shells
to node) preserves D3's "no ~40 ms node startup on every Stop event".

### AD4 — A small `claudespace/channel.py` module owns channel detection (resolves researcher Unknown #2)

Rather than inlining channel logic into `update.py`, factor a ~30-line
`claudespace/channel.py` with `installed_channel() -> "npm" | "pipx"` and
`competing_installs() -> list[Channel]`. Both `update.py` (D6 routing) and
`environment.run_doctor_checks` (D6 competing-install warning) consume it, so
duplicating the detection in two call sites would drift.

**Detection.** Primary signal is a marker file `<sys.prefix>/.claudespace-channel`
written at provision time (npm postinstall writes `npm`; the pipx path is left
markerless and treated as `pipx`). Fallback when the marker is absent: inspect
`sys.prefix` — `…/pipx/venvs/…` ⇒ pipx, a path under `node_modules` ⇒ npm,
else `pipx` (back-compat default, since every install before this change is
pipx). Marker-first keeps it explicit per the ADR; the path heuristic makes it
robust to a hand-moved venv.

### AD5 — Asset sync moves to a guarded first-run in `cli.main()`, for both channels (D4)

D4 requires asset sync out of (root-run) postinstall. The cleanest single code
path is to run it lazily on the first real `claudespace` invocation, guarded by
a per-version sentinel — and to do this for the pipx channel too, so there is
one asset-sync trigger, not two. This is safe: `sync_assets()` only writes under
`Path.home()`, and `cli.main()` always runs as the user. Panes (which fire the
hooks) only exist *after* a `claudespace` launch has run, so hooks are always
registered before any handoff can fire.

**Rejected:** keeping sync in `install.sh` for pipx and moving only the npm
path to first-run. That leaves two triggers and two behaviours to reason about;
D4's root concern is real for npm but the unified first-run path is strictly
simpler and correct for both.

### AD6 — Provisioning and Python discovery branch on `process.platform`; only `darwin` is implemented

`scripts/provision.js` and the postinstall switch on `process.platform`, with
`darwin` fully implemented and `win32` a single clearly-marked `notImplemented`
branch that the psmux work fills (D7/D8). Python discovery is per-OS: macOS
ports `install.sh`'s `find_python` probe order (`python3.14…python3.12`, then
`/opt/homebrew/bin`, `/usr/local/bin`) and Homebrew fallback; `win32` will use
the `py` launcher + winget. `package.json` declares `"os": ["darwin"]` for now,
widened to `["darwin","win32"]` by the psmux work.

## Components

- **`package.json`** (new, root) — name `@ayorcodes/claudespace` (D0), `bin`
  mapping all 7 console-script names to `bin/*.sh` (AD2), `scripts.postinstall`
  → `scripts/postinstall.js`, `"os": ["darwin"]`, `version` synced to
  `pyproject.toml`.
- **`.npmignore`** (new) — excludes tests, `docs/`, `.venv`, `install.sh`,
  `__pycache__`, keeping the tarball to the Python package + `bin/` + `scripts/`
  (~400 KB per the ADR).
- **`bin/claudespace.sh` + 6 siblings** (new) — the committed POSIX shims (AD3).
- **`scripts/postinstall.js`** (new) — D1 global-install guard → D4 venv
  provisioning (no asset sync) → D7 OS-aware preflight.
- **`scripts/provision.js`** (new) — shared venv builder + per-OS Python
  discovery (D8), called by postinstall and by the shims' self-heal (D5).
- **`claudespace/channel.py`** (new) — channel detection/marker (AD4, D6).
- **`claudespace/update.py`** (modified) — route by channel (D6).
- **`claudespace/environment.py`** (modified) — competing-install warning in
  `run_doctor_checks` (D6).
- **`claudespace/cli.py`** (modified) — guarded first-run asset sync in
  `main()` (AD5).
- **`install.sh`** (modified) — reduced to a node-bootstrap shim that installs
  node if absent then runs `npm i -g @ayorcodes/claudespace`, falling back to
  the pipx path only when node cannot be provided (D0).

## Data Flow

### Fresh npm install (`npm i -g @ayorcodes/claudespace`)

```
npm reify → links bin/ shims into the global bin dir (all 7 names on PATH)
         → runs scripts/postinstall.js
              1. D1: assert global install; else fail loudly, naming the
                 correct command, and exit non-zero.
              2. D4: provision venv (scripts/provision.js):
                   - discover Python ≥3.12 (per-OS); offer brew/winget if none (D8)
                   - python -m venv <PKG_ROOT>/.venv
                   - .venv/bin/python -m pip install <PKG_ROOT>   (builds wheel
                     from bundled pyproject.toml → creates all 7 console scripts
                     in .venv/bin, pulls iterm2 from PyPI)
                   - write <.venv-prefix>/.claudespace-channel = "npm"
              3. D7: OS-aware preflight — darwin: .venv/bin/claudespace doctor
                 --yes --no-launch (delegates to detect_usable_backends); win32:
                 notImplemented seam.
```

### First real run (`claudespace` in a project)

```
bin/claudespace.sh → resolve PKG_ROOT → .venv present? (else provision, D5)
  → exec .venv/bin/claudespace
     → cli.main(): require_macos()
        → first-run asset sync (AD5): if sentinel for this version absent,
          sync_assets() (registers Stop+guard hooks, copies commands/prompts),
          then write sentinel
        → normal workspace launch
```

### Hook fire (Stop / PreToolUse), steady state

```
Claude Code fires bare `claudespace-handoff`
  → PATH resolves it to the global-bin symlink → bin/claudespace-handoff.sh
  → resolve PKG_ROOT (.venv already present, no node) → exec
    .venv/bin/claudespace-handoff
```

### Update (`claudespace update`) — D6

```
update.run_update():
  channel = channel.installed_channel()
  if channel == "npm":  subprocess ["npm","i","-g","@ayorcodes/claudespace@latest"]
                        (npm replaces the package dir → .venv gone → its
                        postinstall rebuilds it; marker rewritten)
  else (pipx):          existing clone→pipx uninstall/install path, unchanged
  # sync_assets no longer called here — first-run sentinel is per-version, so
  # the next `claudespace` run re-syncs after either channel's upgrade.
```

## Validation

- **postinstall D1 global check.** Determine the global install by comparing
  the package's resolved directory (`path.resolve(__dirname, "..")`) against
  npm's global root (`npm_config_prefix`, or `child_process` `npm prefix -g`).
  If the package is not under the global root → print the exact command
  (`npm i -g @ayorcodes/claudespace`) and `process.exit(1)`. `npm_config_global`
  is an unreliable secondary hint only; do not rely on it alone.
- **Python version gate (D8).** Provisioner runs
  `python -c "import sys; sys.exit(0 if sys.version_info[:2] >= (3,12) else 1)"`
  against each candidate; refuses with the same actionable message
  `install.sh` uses today when none qualifies.
- **Venv integrity (D5).** Shim treats `.venv/bin/python` missing OR
  non-executable as "needs provisioning".
- **`settings.json` parse.** Unchanged — `_read_settings` already raises an
  actionable error on malformed JSON; first-run sync inherits it.

## Error Handling

Every failure must name which layer failed (ADR risk: "two package managers in
one install path").

- **No Python ≥3.12 and no brew/winget** → provisioner exits non-zero with the
  interpreter-install message; postinstall surfaces it verbatim.
- **`pip install` into the venv fails** (offline, iterm2 build) → provisioner
  prints "venv provisioning failed (pip)" + the pip output, exits non-zero. The
  npm install then reports failure; re-running `claudespace` re-triggers
  provisioning (D5), so a transient offline failure self-recovers.
- **Non-global install (D1)** → loud failure with the correct command; no
  half-install.
- **`--ignore-scripts` (D5)** → no postinstall ran; the shim provisions on
  first invocation (a slow first run, per the ADR).
- **`claudespace update` on npm channel, `npm` not on PATH** → error naming npm
  as the missing tool (mirror `update._require`), do not fall through to pipx.
- **Competing installs (D6)** → `doctor` warns (non-fatal) naming which binary
  PATH resolves first and how to remove the other.

## Security Considerations

- **D4 root safety** is the core security property: postinstall (which may run
  as root under `sudo npm i -g`) writes only inside the package directory
  (`.venv` + channel marker). Nothing under `Path.home()` is touched until the
  user-identity first run. This must be preserved — no `sync_assets()` call, and
  no `~/.claude`/`~/.ai` write, anywhere in postinstall/provision.
- **Marker file** contains a literal channel string only; no secrets, no paths
  from user input.
- Shims `exec` a fixed relative path inside their own package dir; they take no
  path from the environment, so PATH manipulation cannot redirect them.

---

## Performance Considerations

- **Steady-state hook latency (D3).** The shim's happy path is: POSIX readlink
  loop + one `test -x` + `exec`. No node, no Python interpreter spawned beyond
  the console script itself. This is the whole reason shims are `sh`.
- **First run** pays the one-time asset-sync cost (already the case today at
  install time) plus, if postinstall was skipped, venv provisioning. Acceptable
  per D5 ("strictly better than an install that silently produced nothing").
- **Sentinel check** is a single `os.path.exists` on `cli.main()` — negligible;
  it gates the sync so steady-state launches skip the copy work.
- No collection-wide scans introduced; channel detection is O(1) path
  inspection. `competing_installs()` runs only inside `doctor`, not on launch.

## Compatibility

- **Existing pipx users** are untouched: `channel.installed_channel()` returns
  `pipx` for every pre-existing install (markerless), and `update.py`'s pipx
  branch is the unchanged current code. `install.sh` still resolves to the pipx
  path when node cannot be installed.
- **Console-script contract** (7 names) is preserved on PATH by AD2, so the
  handoff/guard/msg/tmux-persist pipeline behaves identically regardless of
  channel.
- **`version`** must stay in lockstep between `package.json` and
  `pyproject.toml`; a release checklist item (Verification) enforces it, since
  npm publishes `package.json`'s version while pip builds `pyproject.toml`'s.
- **Deprecation.** `install.sh`'s pipx path is retained (not removed) as the
  node-less fallback; README leads with npm. No hard deprecation this cycle.

## Edge Cases

- **`sudo npm i -g`** → postinstall runs as root; provisioning writes only
  inside the package dir (D4). First `claudespace` run as the user does asset
  sync. Verify the venv dir is group/other-readable so the non-root user can
  execute the console scripts (venv created by root under the global prefix is
  the normal npm global situation — the shims are world-executable as npm links
  them; ensure `provision.js` does not `chmod` them narrower).
- **`--ignore-scripts` / pnpm** → self-heal on first shim call (D5).
- **npm update replaces the package dir** → `.venv` vanishes with the old dir;
  the new version's postinstall rebuilds it. This is D2's "rebuild automatic on
  version bump" — confirm empirically (Verification).
- **Both pipx and npm installed** → `doctor` warns (D6). `update` routes by the
  *running* binary's channel, so updating the one on PATH does the right thing;
  the shadowed one is reported, not auto-removed.
- **`npm rm -g @ayorcodes/claudespace`** removes the package dir + `.venv` (D2)
  but NOT the hooks/commands written under `~/.claude` at first run. npm 7+ has
  no reliable global uninstall lifecycle script, so this cannot auto-run
  `claudespace uninstall`. Left-behind hooks point at a now-missing command and
  fail every turn (the D1 failure, post-uninstall). **Mitigation:** README and
  `doctor` instruct running `claudespace uninstall` *before* `npm rm`. Tracked
  in Open Questions.
- **Custom global prefix / nvm** → D1 check must use the *actual* resolved
  global root, not a hardcoded `/usr/local`, or it false-positives on nvm-style
  prefixes. Covered by using `npm prefix -g` / `npm_config_prefix`.
- **Symlinked bin resolution** → shim's readlink loop must terminate on a
  non-symlink and handle relative link targets (resolve against the link's
  dir). Unit-test the resolver in isolation.

## Tests Required

New test modules follow the repo's one-module-per-source rule.

- **`tests/test_channel.py`** (unit) — `installed_channel()` returns `npm` with
  a marker present, `pipx` markerless; path-heuristic fallbacks
  (`…/pipx/venvs/…`, `…/node_modules/…`, unknown→pipx); `competing_installs()`
  detects both, one, none.
- **`tests/test_update_channel_routing.py`** (unit) — `run_update()` invokes
  `npm i -g …@latest` when channel is npm (mock `subprocess`/`shutil.which`),
  and the existing pipx path otherwise; missing-`npm` error path.
- **`tests/test_cli_first_run_sync.py`** (unit) — `main()` calls `sync_assets`
  when the version sentinel is absent, skips it when present, writes the
  sentinel after a successful sync; sync failure does not write the sentinel.
- **`tests/test_environment.py`** (extend) — `run_doctor_checks` emits the
  competing-install warning (non-fatal, exit unchanged) when
  `competing_installs()` reports two.
- **Shim resolver** — a shell-level unit test (invoke `bin/claudespace.sh`
  through a symlink into a temp `.venv` stub, assert it execs the right target;
  assert the missing-`.venv` branch calls the provisioner). Runs under the
  existing `shellcheck`/CI shell lane.
- **Integration (macos-latest, manual/CI smoke)** — `npm pack` → install the
  tarball globally into a throwaway prefix → assert all 7 names resolve, `.venv`
  exists with the marker, `doctor` runs; `--ignore-scripts` install → first
  shim call provisions; `npm rm -g` removes package dir + `.venv`.
- `shellcheck -s sh bin/*.sh` and the reduced `install.sh` (CI shell lane).

## Implementation Order

1. **`claudespace/channel.py`** + `tests/test_channel.py` — no dependencies;
   unblocks D6 work. Define the marker path and `installed_channel()` /
   `competing_installs()`.
2. **First-run sync in `cli.py`** (AD5) + `tests/test_cli_first_run_sync.py` —
   move the asset-sync trigger; add the per-version sentinel helper. Independent
   of npm packaging, and required before postinstall stops calling sync.
3. **`update.py` channel routing** (D6) + `tests/test_update_channel_routing.py`
   — consume `channel.py`; keep the pipx branch byte-for-byte.
4. **`environment.run_doctor_checks` competing-install warning** (D6) + extend
   `tests/test_environment.py`.
5. **`scripts/provision.js`** — per-OS Python discovery (darwin full, win32
   stub), `python -m venv`, `pip install <PKG_ROOT>`, write channel marker.
6. **`bin/*.sh` shims** (AD3) — 7 committed POSIX shims with the readlink
   resolver + self-heal; shell unit test; `shellcheck`.
7. **`scripts/postinstall.js`** (D1 guard → provision → D7 preflight).
8. **`package.json` + `.npmignore`** — `bin` (all 7), `os`, `postinstall`,
   version synced to `pyproject.toml`.
9. **Reduce `install.sh`** to the node-bootstrap shim with the pipx fallback
   (D0); keep the pipx path callable.
10. **Docs** — README leads with `npm i -g @ayorcodes/claudespace`; document
    the `claudespace uninstall`-before-`npm rm` step; note pipx as the
    Python-native alternative. (Per repo convention, commit the `docs/`
    pipeline artifacts with the change.)
11. **CI** — add the npm-pack/global-install smoke lane on `macos-latest`
    alongside the existing `pytest`/`shellcheck` jobs.

Steps 1–4 are pure-Python and land/verify independently of 5–8 (the npm
tarball), so the pipx channel keeps working throughout. Steps 5–9 make the npm
channel real; 9 only lands after 5–8 verify, so `install.sh` is never pointed
at an unpublished package.

## Open Questions

- **Q: How should hooks/commands under `~/.claude` be cleaned up on `npm rm`,
  given npm 7+ has no reliable global uninstall script? → A (decided
  autonomously):** ship the documented `claudespace uninstall`-before-`npm rm`
  step and a `doctor` reminder now; a wrapping `claudespace self-remove` that
  runs both is a follow-up, not blocking. Rationale: matches the ADR's "keep it
  boring", avoids depending on removed npm lifecycle behaviour, and the failure
  is a stale hook the user can clear with one command. Revisit if it bites.
- **Q: `uv venv`/`uv pip` vs stdlib `python -m venv` + `pip` for provisioning
  (D2 permits either)? → A (decided autonomously):** stdlib `venv`+`pip`, to
  avoid adding `uv` as a second unmanaged prerequisite alongside node and
  Python. `uv` is a speed optimisation the provisioner can adopt later behind a
  `shutil.which("uv")` check without changing the design.
